# Project plan for WholphinFluid

## Purpose

WholphinFluid is a fork of Wholphin focused on a fluid, modern Android TV experience for Jellyfin. This project board is intended to keep work organized around design, features, product polish, and maintenance.

## Goals

- Improve the experience for Jellyfin users on Android TV and Fire TV
- Keep the app responsive, readable, and easy to navigate
- Preserve compatibility with current Jellyfin server versions
- Deliver refinements around home screen UX, playback, and accessibility
- Maintain a clear backlog for contributors and maintainers

## Workstreams

### 1. UX and design
- Fluid home page layout and hierarchy
- Improve visual consistency and spacing
- Refine library browsing and detail screens
- Improve focus states and navigation clarity

### 2. Navigation and discoverability
- Improve app navigation from home to libraries to settings
- Simplify access to favorites, search, and collections
- Improve discoverability of core actions

### 3. Playback and media experience
- Playback controls and responsiveness
- Better chapter/queue handling
- Subtitle, audio, and media compatibility polish
- Performance and stability of streaming experiences

### 4. Accessibility and usability
- Screen-reader, keyboard, and focus handling improvements
- Better contrast and legibility
- Reduce friction for first-time users

### 5. Stability and maintenance
- Dependency upgrades and Android compatibility maintenance
- Bug triage and regression prevention
- Build and CI health
- Cleanup and technical debt reduction

## Definition of ready

A task is ready to plan when it has:
- a clear objective
- scope and expected outcome
- acceptance criteria or verification notes
- links to related screens, issues, or context when needed

## Definition of done

A task is done when:
- the work is implemented and reviewed
- validation or testing notes are included
- related documentation or follow-up items are updated if needed
- it is moved to the Done column and linked to the relevant branch or PR

## Contribution flow

1. Open or review an issue
2. Move it to Planned or In Progress
3. Implement the work in a feature branch
4. Open a PR with a clear summary and testing notes
5. Move the issue to Review after PR creation
6. Close or archive once merged

## Notes

This project board is intentionally lightweight. It is designed to keep the work visible without over-complicating the repo. The goal is to make it easier to prioritize fluid improvements and keep contributor work aligned with the app's direction.
